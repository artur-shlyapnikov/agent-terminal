# ADR-0001: Single-process MVP (no runtime daemon)

- Status: Accepted
- Stage gate: Repository & dependency boundary (architecture §6.1)
- Supersedes: none

## Decision

The AgentTerminal MVP is a **single macOS application process**:

- Native AppKit app owns UX (`App/`).
- `libghostty` owns local PTYs and terminal processes, embedded in-process via
  the pinned xcframework behind `GhosttyBridge`.
- `AgentRuntime` owns lifecycle semantics in-process (`AgentCore`).
- SQLite owns durable metadata through GRDB (`AgentStore`).
- A local Unix-socket control API serves hooks and automation
  (`AgentControl`, consumed by the `agentctl` CLI and helper executables).

We explicitly reject a separate PTY/runtime daemon for the MVP. The daemon
migration seam is preserved by keeping every cross-boundary interaction behind
the `TerminalControlling` / `StatePersisting` ports and the versioned control
protocol v1 (see `docs/Protocols/control-v1.md`).

## Rationale

1. The current libghostty embedder API has no stable "render an external PTY
   byte stream" mode, so a GUI over an external server would have to re-implement
   terminal rendering against a moving internal API (architecture §2.5).
2. A GUI/server split would put double models of focus, panes, keyboard
   handling, and lifecycle into the very first milestone.
3. Inter-process communication errors would become part of MVP scope without any
   user-visible benefit at this scale (single machine, single user).
4. Window close must keep agents alive; that requires only that surfaces park
   into a hidden host window while the process stays running (§3.15) — not a
   second process.

## Consequences

- Positive: one process to debug; no IPC protocol on the hot path; surfaces have
  natural main-thread affinity.
- Negative: a crash of the app kills all live agents (mitigated by crash
  recovery and resume-later marking, §3.15); full quit intentionally stops all
  agents and is communicated in UX.
- Deferred cost: migrating to a daemon later means promoting the control
  protocol from local socket to the same wire format — kept cheap by freezing
  protocol v1 envelopes now.

## Structure-mapping appendix: plan paths → repository reality

Two plan conventions could not be used verbatim; the mapping below is binding.

### 1. `Helpers/` prefix → SwiftPM executable targets inside `Packages/`

SwiftPM forbids target sources outside the package root, so the plan's
top-level `Helpers/AgentLauncher/main.swift` and `Helpers/AgentCTL/main.swift`
(§4.7) physically live at:

| Plan path | Actual path | Notes |
|---|---|---|
| `Helpers/AgentLauncher/main.swift` | `Packages/Sources/AgentLauncher/main.swift` | SPM executable target `AgentLauncher`; product of the same name |
| `Helpers/AgentCTL/main.swift`, `Commands.swift` | `Packages/Sources/agentctl/*.swift` | SPM executable target `agentctl` |
| `Helpers/Integrations/*` (hook shims, installer) | `Packages/Sources/IntegrationTools/*` when they need compilation; pure scripts stay under `Resources/Integrations/<agent>/` | Decided when integrations land (Stage 14); scripts never compiled |

The app project does not duplicate these sources: `App/project.yml` defines
native `tool` targets whose `sources:` point back into
`../Packages/Sources/<Name>` so the binaries can be copied into
`Contents/Helpers/`. One source of truth, two build systems.

Dependency rule for helpers is unchanged and enforced by imports:
**helpers depend on AgentControl protocol models only, no AppKit.**

### 2. `Docs/…` capitalization → lowercase `docs/…`

The plan's §4.1 table uses capitalized `Docs/Architecture/…` paths. The
repository already contains a lowercase `docs/` directory holding the source
architecture document, which must not be moved or renamed. All documentation
therefore lives under lowercase `docs/`:

| Plan path | Actual path |
|---|---|
| `Docs/Architecture/ADR-0001-single-process-mvp.md` | `docs/Architecture/ADR-0001-single-process-mvp.md` |
| `Docs/Architecture/ADR-0002-libghostty-boundary.md` | `docs/Architecture/ADR-0002-libghostty-boundary.md` |
| `Docs/Architecture/ADR-0003-agent-lifecycle.md` | `docs/Architecture/ADR-0003-agent-lifecycle.md` |
| `Docs/Protocols/control-v1.md` | `docs/Protocols/control-v1.md` |
| `Docs/Detection/manifests.md` | `docs/Detection/manifests.md` |
| `Docs/Security/threat-model.md` | `docs/Security/threat-model.md` |

### 3. `AgentTerminal.xcworkspace` → committed minimal workspace file

The plan's §4.1 workspace deliverable is a hand-written minimal
`AgentTerminal.xcworkspace/contents.xcworkspacedata` at the repository root,
listing `App/AgentTerminal.xcodeproj` (generated by xcodegen) and
`Packages/Package.swift`. XcodeGen does not generate workspaces, so the file is
committed directly and verified by
`xcodebuild -workspace AgentTerminal.xcworkspace -scheme AgentTerminal build`.
